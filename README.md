# AI 智能体辅助管理平台

Electron、React 和 TypeScript 实现的光储直柔监控平台。

每次进入或刷新主程序后，自动告警弹窗及语音播报先等待 10 秒；到时仅提醒仍然存在的告警。数据刷新及程序内页面切换不会重新计时，等待结束后的新告警按原有流程触发。

## 显示字号

在「设置中心 → 显示设置」选择整体字体大小：90%、100%（默认）、110%、120%、130%。选择后立即生效，覆盖导航、正文、表单、图表和能源示意图文字，并保留原有字号层次。设置保存在当前设备的本地存储中，重新打开后自动恢复；同一来源的其他窗口同步更新。点击「恢复默认字号」回到100%。

运行 `npm run test:font-size` 验证五档字号、页面切换、图表和画布文字、重启恢复、存储异常及最大字号下的主要页面布局。测试使用临时数据和隐藏窗口，不连接现场设备。

## 系统架构改造演示

进入「综合监控」时，系统图默认展示「传统交流模式架构图」。两种模式共用同一套设备、布局和实时数据：电网及通信接口、变流设备、4 路光伏组串、储能系统，以及一级直流灯、二级直流风扇、三级直流电机。传统模式不再额外绘制变压器、充电桩、空调、电子设备或独立电源转换器；交流母线、光伏逆变及负载侧 AC/DC 路径标注用于演示改造前的转换环节，升级后切换为直流母线和 DC/DC 直供路径。

点击右下角「综合变换效率」会用黄色区域高亮变换路径，并放大显示「综合效率91.20%」，通过平台统一语音播报传统模式说明。点击「更新架构」后，按钮旋转并显示切换动画，约 1.4 秒后切换为「光储直柔模式架构图」；再次点击效率按钮，高亮 DC/DC、直流母线与负载供电路径，显示「综合变换效率约97.00%」并播报效率提升说明。底部按钮随后显示「还原架构」，点击可切回传统交流模式，支持反复往返演示；两个方向均保留切换动画，并在切换时清除旧高亮、停止旧播报，防止重复点击。两项效率为项目指定的演示数值；切换仅改变可视化架构，不向 PLC 写入参数。离开监控页后重新进入，默认回到传统模式。

效率讲解只保留图内高亮、效率数值和语音，不再展示底部说明栏。「综合变换效率」为循环开关：第一次点击显示高亮并播报，再次点击收起高亮与效率数值、停止播报，下一次点击重新显示并播报。播报完成、加载中、失败或被浏览器拦截时，点击仍会关闭；关闭后可再次开启重试。按 Esc 也可收起高亮并停止播报。更新架构及离开页面会取消旧语音和未完成的更新计时。系统的减少动态效果设置会关闭旋转和放大动画，保留模式切换。

运行 `npm run test:energy-architecture` 验证两种拓扑、效率讲解、更新动画、语音恢复/取消以及 760px 窗口与 130% 字号布局。测试使用隔离 Electron 窗口和模拟音频，截图目录可通过 `ENERGY_ARCHITECTURE_SCREENSHOTS` 指定。`npm run test:energy-power` 继续验证升级后的实时功率显示。

## 智诊精巡双 AI

智诊精巡可切换「高精度智能运维系统」与「智能数据分析系统」，分别保存图片诊断和农光互补方案会话。智能数据分析系统按提供的演示文案完成两轮流程：

1. 上传 Word 项目信息（`.doc` / `.docx`），附件先暂存；点击「语音输入」逐字显示「请结合附件的农光互补项目信息，综合分析光伏支架安装高度以及倾角调节技术方案建议」。确认文字并发送后等待 **5 秒**，逐行展示分析过程，再渐进输出最低净高计算、三类方案的六维对比表。结论「本项目光伏支架最低净空高度取 2.0 m，建议采用方案三的倾角调节方式。」加大加粗，并通过平台语音自动播报；第一轮不生成工单。
2. 再次点击「语音输入」，显示「请你提供按季动态倾角加茶树全生长周期的倾角调整建议。」发送后同样等待5秒，展示第二轮分析和四季建议。输出完成后生成待审核工单，加大加粗显示当前日期、季节和生成状态，并自动播报四季策略及结论。工单生成失败时提供重试，不播报成功；重试复用同一请求，避免重复创建。

底部需求框支持编辑、Enter发送、Shift + Enter换行，最多2000字。模拟输入不申请麦克风、不录音、不调用识别服务；可提前「结束说话」填入完整台词，或取消恢复草稿。离开助手时暂停分析并停止播报，返回继续；刷新后未完成分析显示「重新生成」。历史结果不自动重播。自动播放被浏览器拦截时显示「点击播放」，可恢复已生成音频。

语音输入按约每秒3.4个字的节奏逐字显示，字间间隔在270～320毫秒之间轻微变化，逗号等分句标点后停顿480毫秒，句末标点后停顿700毫秒，再继续下一句。

演示台词、完整分析文案、表格内容、输出节奏及季节策略集中在 `src/shared/agrivoltaic-analysis.ts`。当前分析每650毫秒追加一段、答案每25毫秒增加一字；统一控制节奏，不依赖外部模型的实时响应速度。这里只保存附件名称、大小和需求原文，不读取或解析 Word 内容，展示的是用户指定的演示数据与政策文案，不代表已核验附件政策。

日期取提交时平台右上角时钟（上海时区，PLC同步，未同步时使用本机时钟）。按项目四次物候节点固定划分：2月4日进入春季、5月6日进入夏季、8月8日进入秋季、11月8日进入冬季；维持周期截止下一节点前一天。基准倾角21–23°，中心值22°，春季20°±1°、夏季19°±1°、秋季22°±1°、冬季34°±1°。例如2026年9月23日生成 `NG-GQ-20260923-001`，目标22°±1°，维持至2026年11月7日；冬季跨年维持至次年2月3日。历史旧版季节工单保留旧角度范围。

工单包含项目名称、作业名称/日期、09:00–17:00执行时段、天气限制、手动支架阵列、三项调整依据、目标倾角及维持周期，在对话、工单中心和C平台均可查看。选手手动点击「下发工单」后现场才收到任务。新建季节工单按B作业前检查、C现场实施、A完工验收的顺序执行；历史工单保留原有流程。清空聊天不会删除工单。

运行 `npm run test:tilt` 验证两轮台词、附件等待发送、5秒边界、逐行分析与渐进表格、自动语音/播放恢复、四季和跨年日期、历史兼容、重试去重、人工下发、C平台接收与回填。测试使用临时数据库、隐藏Electron窗口和模拟音频，不连接现场设备。开发命令 `npm run dev` 会监听后端与预加载代码并重启Electron，部署更新后需重启平台与刷新Pad页面。

## C 平台表单与图片回传

C平台名称为「智诊精巡-高精度只能运维系统」（按需求原文）。新季节工单下发后，A、B、C三台Pad均收到统一语音，例如「您有新的工单，请将光伏组件倾角调整至 22°。」角度由工单保存的季节策略决定。各Pad需先点击开启语音以满足浏览器播放要求，支持重新播报。

三人都能查看与B平台一致的工单基本信息。B同学填写4项作业前检查、原始倾角与照片编号；C同学填写5项作业实施记录和调整后的实测倾角；A同学填写5项完工验收、抽检数量及档案编号。每人逐项勾选、上传至少一张照片并填写签字姓名后提交，日期时间由平台时钟自动记录。C的实测倾角须落在该工单的允许范围内。B提交后解锁C，C提交后解锁A，三人全部提交后继续已有的PLC验证关单流程。

所有任务的「结果回传」均支持照片上传；支持设备的「拍照 / 选图」入口会调用系统相机，否则可选择已有照片。每个任务最多6张JPG、PNG或WebP；单张原图上限20MB，超过3MB时前端压缩，入库上限3MB。照片保存在平台SQLite数据库，刷新后可恢复已上传照片；提交后在B平台「工单中心 → 人员任务」查看表单、签字和照片，点击缩略图放大。未提交照片可移除，已回传照片不可改删。

运行 `npm run test:pad-fields` 验证三角色表单、顺序解锁、必填校验、图片上传及数据库持久化、刷新恢复和B平台预览。测试使用隔离数据库及随机本地端口，截图默认写入系统临时目录，可用 `PAD_FIELD_SCREENSHOTS` 指定位置。

## PLC Modbus TCP

应用默认通过 Modbus TCP 连接 `192.168.0.1:503`，每秒使用功能码 `03` 分段读取零基 Holding Register `HR200–HR303`、`HR55–HR59`、`HR100`、`HR105`，每段不超过 125 个寄存器。PLC 标签中的 M 区字节地址按“字节地址 ÷ 2”换算为寄存器地址。四路光伏电压、电流按大端无符号 16 位 `WORD` 读取，原始值除以 `100` 后供平台显示和计算；蓄电池仍使用大端 IEEE-754 `REAL`。同一寄存器内，偶数 M 字节地址映射高字节，奇数 M 字节地址映射低字节。

可通过环境变量覆盖连接参数：

```bash
PLC_HOST=192.168.0.1 \
PLC_PORT=503 \
PLC_UNIT_ID=1 \
PLC_POLL_INTERVAL_MS=1000 \
npm run dev
```

如需脱离 PLC 使用模拟数据，可设置 `PLC_MODE=simulation`。模拟模式下的光伏 1–4 电压/电流依次为 `210 V / 19 A`、`210 V / 19 A`、`222 V / 21 A`、`220 V / 20 A`，蓄电池为 `52 V / 5 A`；PLC 时钟从 `2026-09-01 15:30:30` 开始按采样周期递增。

## PLC 点位调试网页

主监控右上角的时间只读显示，随 PLC 采集结果同步并持续走秒。`/plc` 调试页保留时钟点位的编辑、写入及回读核对。使用平台时钟的业务继续跟随 PLC 时间。

启动平台后，打开 `http://127.0.0.1:17880/plc`，或从管理端「设置中心 → PLC 点位调试」进入。同一局域网的电脑、手机可通过 `http://运行平台电脑的Wi-Fi地址:17880/plc` 访问；页面顶部提供当前局域网链接。运行平台的电脑需要能连接 PLC。这里提供的是局域网访问地址，公网访问需要另行配置网络入口。

1. 填写真实 PLC 的 IP、TCP 端口、Unit ID，以及寄存器偏移（默认 `0`，地址使用零基 HR），点击「连接并读取」。初始参数来自平台的 `PLC_HOST`、`PLC_PORT`、`PLC_UNIT_ID`、`PLC_REGISTER_OFFSET`；读取成功后在当前浏览器记住连接参数。
2. 编辑四路光伏、蓄电池的电压、电流或 7 个功率点位，点击该行「写入」，或勾选多行后点击「写入已选点位」。光伏电压/电流输入换算后的 V/A 数值（`0–655.35`，最多 2 位小数），写入时自动乘以 `100`，例如 `123.45` 写入原始值 `12345`。功率输入 `0–65535` 的整数 kW，直接写入原值。空值和无效数值不会提交，未勾选的点位不会写入。
3. 读取成功后可编辑 PLC 时钟的年、月、日、时、分、秒、星期，或点击「填入本机时间」，再点击「写入 PLC 时间」整组提交并回读核对。「读取 PLC 时间」刷新当前读数并保留待写值。星期采用现有映射：`1=周日`、`7=周六`。
4. 查看逐项写入结果，包括提交值和回读值。批量写入逐项执行，不是整个批次的原子事务；遇到拒绝、回读不一致、连接中断或超时，就停止后续点位。状态未确认时应先重新读取，不会自动重试写入。

读写通过平台后端完成：功能码 `03` 读取，功能码 `16 / 0x10` 写保持寄存器。每个光伏 WORD 只写一个寄存器，避免覆盖相邻点位；每个蓄电池 REAL 的两个寄存器一次写入，并保持既有大端字节序；时钟的四个寄存器整组写入；每次写入应答后立即回读比较。协议参考 [Modbus 官方规范](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf)。时钟写入针对映射的 M 区变量，是否同步到 PLC 系统时钟取决于 PLC 程序。PLC 需要开放相应寄存器及写入功能；如果梯形图/PLC 程序在每个扫描周期刷新这些 M 区变量，手动写入的值可能很快被覆盖，页面会报告回读不一致。

调试目标独立于主监控采集配置，修改调试页面 IP 不会切换监控采集目标。当 IP、端口、Unit ID、寄存器偏移与主监控相同时，调试读写复用采集器的同一条 TCP 连接；整个读取或写入加回读操作排队执行，兼容只允许一个连接的 PLC。其他目标使用独立连接。主监控会在后续采样中显示实际读数。连接中断后采集可以重连，但未确认的写入不会自动重试。调试接口即使在平台模拟模式下也操作指定的真实设备。写入请求与结果记录在本地事件日志中。

验证读写实现（仅连接本机临时 Modbus 服务，不操作真实设备）：

```bash
npm run test:plc
npm run test:plc-session
npm run test:energy-power
```

## Pad 局域网访问地址

### 全平台语音

告警、AI 诊断、倾角分析、工单关闭提醒、Pad 员工任务和能效讲解统一使用试听确认的 **婷婷普通话女声**（185 语速，24 kHz 单声道 PCM WAV）。固定文案播放整段录音；工单编号、日期、角度及变化文本按最长短语匹配组合预录片段。常用汉字和英文字母也有同音色录音，以覆盖新增设备名称和任务内容。动态片段之间的衔接不如整段录音自然；常用新文案可加入录音目录后重新生成。

管理端 `/api/speech` 只读取和组合随包音频，不调用云端接口、系统 TTS 或原来的离线模型。旧版云端配置及环境变量不会改变音色；设置中心只提供统一音色说明和试听。运行和 Windows/Linux 打包均不需要 macOS、语音密钥或联网下载语音引擎。安卓 Pad 通过局域网从管理端获取相同音频。

每次打开员工任务页需点击开启播报。浏览器拦截自动播放时保留已加载音频，点击播放即可恢复。只有完整播放结束才记录为已播；中断、失败、切换角色不会误标完成。全平台共用同一播放通道，新播报会停止上一段。缺失语音包、损坏文件或未收录的生僻字会明确报错，不切换到其他音色、不省略安全提示。常用数字、日期、百分比和单位在播放前统一转换为中文读法。

音频资源在 `resources/recorded-speech/`，包括清单和按 16 MiB 分卷保存的 PCM 数据，须随源码一同保留。`npm run prepare:speech` 校验所有文件的 SHA-256；开发启动和打包会自动执行校验，资源缺失会阻止打包。安装包通过 `extraResources` 携带同一套音频，不再打包原离线模型。

新增整段录音时编辑 `scripts/recorded-speech-catalog.ts`；仅在安装了婷婷音色的 Mac 上运行 `npm run generate:speech` 重新生成。生成工具复用本地缓存，发布构建只校验已生成文件。

运行 `npm run test:speech` 验证真实录音、动态文字完整性、API 缓存、统一音色、AI/工单/告警和 Pad 播放状态；`npm run test:tilt`、`npm run test:energy-architecture` 覆盖倾角与能效讲解。`SPEECH_SMOKE_RESOURCES` 可指向安装包 resources 目录，`SPEECH_SMOKE_OUTPUT` 可保存真实固定及动态试听 WAV。Windows CI 同时检查开发目录和安装包中的资源。更新后需重启管理端，并刷新员工任务页；现场安卓设备实际发声仍需在设备上验证。

### 访问配置

内置服务仍监听所有网卡，但管理端生成和分享的 Pad 地址固定使用 Wi-Fi 网卡的 IPv4 地址。Windows 会优先根据系统报告的 NDIS 无线物理介质识别真实 Wi-Fi 网卡，不依赖网卡显示名称；macOS 默认识别 `en0`，Linux 默认识别常见的 `wlan`/`wlp` 网卡。

如果设备的 Wi-Fi 网卡名称不同，可用 `APP_WIFI_INTERFACE` 明确指定：

```bash
APP_WIFI_INTERFACE=en0 npm run dev
```

Windows PowerShell 示例：

```powershell
$env:APP_WIFI_INTERFACE='Wi-Fi'
npm run dev
```

Wi-Fi 网卡没有活动 IPv4 地址时，应用会在终端打印警告并把分享地址限制为 `127.0.0.1`，不会自动切换到有线或虚拟网卡；应用本身仍可在本机启动。建议在路由器中为运行软件的电脑设置 DHCP 地址保留，避免分享链接随 Wi-Fi 地址变化。
